# 会话结束自动提交

每次会话结束前，如果本次对话对仓库文件做过任何修改（新增/编辑/删除，不含用完即删的临时脚本），必须把改动提交到 git，避免内容丢失。

## 何时提交
- 在一次任务完成、准备把结果交回给用户之前提交。
- 只要工作区有本次会话产生的实质性改动（`git status` 有变化），就提交。
- 如果本次会话没有改动任何文件，跳过，不要产生空提交。

## 怎么提交
1. 先 `git status` 看清改了哪些文件。
2. 只 `git add` 本次会话实际改动的文件，按文件名逐个添加，不要用 `git add -A` / `git add .`，避免把无关文件带进去。
3. 提交信息用中文，简述本次做了什么，例如：
   `test: 新增期权冻结解冻批量导入用例文件`
   `fix: 还原 stock_frozen.xlsx 被误删的行与列`
4. 只提交到当前分支，不要 push，除非用户明确要求。

## 安全红线
- `db.py`（含四套环境明文密码）已在 `.gitignore`，禁止用 `git add -f` 等方式强行提交它。
- 提交前留意有没有新的、含明文密码/私钥的文件被带入；有的话先问用户，不要自行提交。
- `config.py` 里的 `AUTHORIZATION` 是会过期的登录 token，按现状随其它测试脚本一起提交即可（用户已知悉）。
- 不修改 git 配置，不做 force push / reset --hard 等破坏性操作。

## 清理
- 提交前先删掉本次会话产生的临时脚本（如 `_tmp_*.py`、`_*.txt`），它们不该进入提交。
