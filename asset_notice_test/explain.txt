USSGZT-9963 【SG】已注销用户股票抵押比率变更发送通知告警优化

【类型】改进
【状态】SIT测试
【项目】asset-center-sg
【分支】feature-260821-删除告警日志
【SIT分支】SIT-20250707

【问题描述】
历史遗留问题，有些用户已经注销，但是还存在碎股持仓。当改碎股对应的抵押比率变更的时候
会发送邮件通知。由于该用户已经注销，查询不到用户信息，会在告警群告警。
现优化成这部分用户只打印日志，不在告警群告警。

【改动本质】
告警降噪。功能行为不变，只是把「查不到用户」这个分支的企业微信告警去掉，改为只打 log.warn。

【开发提供的日志锚点】

1) 核心验证点 —— 改造后的样子：只打日志，无 sendTxtMessage

   log.warn("用户ID[{}]没有找到用户，请检查", notice.getUserId());

   日志搜索关键字：没有找到用户，请检查

2) 另一个分支 —— 注意别搞混：这个分支仍然会往告警群发消息

   if (!shouldSendNoticeToUser(notice, userInfo, email)) {
       debugHelper.info("跳过不应该向用户发送的通知，通知内容：{}", JSON.toJSON(notice));
       wxChatbotAgent.sendTxtMessage("跳过发送孖展比率通知，通知可能已经超过有效期，请检查通知，通知："
           + JSON.toJSONString(notice), WARNING_LIMIT_MINUTES, false);
       continue;
   }

   日志搜索关键字：跳过不应该向用户发送的通知

   ★ 这一段的 wxChatbotAgent.sendTxtMessage 没有被删除，是「通知超过有效期」的告警。
     如果在告警群看到消息，先确认是不是这一条，不要误判为本次改动失效。

  本次要盯：环境=sit，服务名=asset-center-sg，级别=WARN

【概念说明：抵押比率 vs 保证金率】
抵押比率 = 这只股票能拿去跟券商借多少钱（券商出的部分）
保证金率 = 买这只股票你自己要掏多少（自己出的部分）
数学上互补：抵押比率 70% <=> 保证金率 30%，加起来 100%。

★ 但「数学上互补」不等于「系统里是同一个字段」。
  系统一般只存一个字段（通常是抵押比率 / marginRatio），另一个是算出来的。
  如果后台还有独立的「保证金率」输入框，那很可能属于另一张表、另一套业务
  （期权保证金 / CFD 保证金），改它不会触发本次的抵押比率变更通知。
  => 测试前必须确认「改哪个字段才会触发通知」，改错字段会导致通知不发、
     日志搜不到，误判为改动失效。

  另注：期权 / 期货的「保证金率」是独立算法（按合约名义价值、SPAN/delta 等），
  与抵押比率没有互补关系，不要套 1 - x 的公式。

【待开发确认（4 项，直接影响能否测通）】
1. log.warn 分支的实际触发条件：是用户表记录不存在，还是查询带了「状态=已注销」过滤返回 null？
   —— 决定造数据是「删记录」还是「改状态」。搞错了走不到该分支，会得到假的通过。
2. 抵押比率变更通知是定时任务触发还是 MQ 触发？cron 表达式是多少？能否手动触发一次？
   —— 决定改完比率要等多久。
3. SIT 环境日志级别是否开到 WARN 及以上，log.warn / debugHelper.info 是否会被过滤掉？
4. 通知监听的是哪张表、哪个字段的变更？后台对应的是哪个配置入口？
   （抵押比率 与 保证金率 是两个独立入口，见下方"后台入口"，已确认）

【后台入口（已通过页面截图确认）】

★ 正确入口：菜单「保证金比率管理」-> tab「股票抵押比率变更」
  列表字段：股票名称 / 股票代码 / 市场 / 变更前抵押比 / 变更后抵押比率 /
           生效状态 / 变更生效时间 / 有效截止日 /
           变更前融资保证金算法 / 变更后融资保证金算法 / 更新人 / 更新时间
  数据示例：CHINA TAIPING  00966  HK  0.5 -> 0.4
           生效时间 2026-05-27 18:30:00，有效截止日 2099-12-31，生效状态 SUCCESS
  注意：抵押比率这里用小数表示（0.5 = 50%），不是百分数。
       抵押比率与「融资保证金算法」（如 C(30%, 25%) / B(25%, 20%)）是一起变更的。

✗ 不要用：tab「保证金设置」/「IB保证金」
  字段是 多头初始保证金率 / 多头维持保证金率 / 空头初始保证金率 / 空头维持保证金率
  这是保证金那一套，与本次抵押比率变更通知无关，改它不会触发通知。

【触发机制（由页面字段推断）】
「股票抵押比率变更」带有「变更生效时间」+「生效状态」两个字段，说明变更是
预约制：填一个未来时间，由定时任务扫描到期记录并执行，执行时发送通知。

  => 测试操作：新增一条变更记录，生效时间设为几分钟后，等「生效状态」变 SUCCESS，
     再去查日志 / 看告警群。
  => 「生效状态 = SUCCESS」是关键信号：它证明变更确实执行了。此时若日志里搜不到
     warn，说明是真问题，而不是"没触发"。

【「有效截止日」与超有效期告警的关系】
通知带有效期。若定时任务延迟太久才处理，就会走
  shouldSendNoticeToUser -> false -> "跳过发送孖展比率通知，通知可能已经超过有效期"
这个分支，而该分支的 wxChatbotAgent.sendTxtMessage 本次并未删除，仍然会告警。
=> 构造 REG-02 时可以利用这一点（把生效时间设为较早时间制造延迟）。
